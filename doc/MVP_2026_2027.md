# Guida MVP TheBitLab per l'anno scolastico 2026/2027

## A chi serve

Questa è la guida operativa di ingresso per il pilot. Il docente usa Course Board, activity e dashboard; lo studente usa dashboard e CLI/TUI. Per dettagli tecnici vedere [Architettura MVP](ARCHITETTURA_MVP.md).

## Prerequisiti pilot

- Python 3.11-3.13;
- dipendenze di sviluppo, uTUI e autenticazione;
- Docker per il grading sandbox;
- HTTPS stabile per login federato in rete;
- segreti esterni al repository;
- una sola istanza applicativa per root dati;
- backup configurato prima di usare dati reali.

Installazione locale:

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements-dev.txt -r requirements-utui.txt -r requirements-auth.txt
```

Su Linux/macOS sostituire l'attivazione con `source .venv/bin/activate`.

## Avvio rapido senza autenticazione federata

```powershell
python scripts/course_board_server.py
```

Aprire:

- Course Board: `http://127.0.0.1:8765/tools/course_board.html`
- Calendario: `http://127.0.0.1:8765/tools/school_calendar.html`
- Dashboard docente: `http://127.0.0.1:8765/tools/assignment_dashboard.html`
- Vista studente locale docente/demo: `http://127.0.0.1:8765/tools/student_dashboard.html`

La password docente mostrata all'avvio non va copiata in ticket, screenshot o log condivisi.

## Fonti GitHub private

Prerequisiti:

1. GitHub App con `Contents: read-only` e metadata read-only;
2. installazione limitata ai repository didattici;
3. configurazione esterna protetta in `~/.thebitlab-secrets/github-app/runtime.json`;
4. chiave privata RSA esterna;
5. nessun token nel design o nell'ambiente.

Avvio:

```powershell
python scripts/course_board_server.py --enable-github-app-token-runtime
```

In **Gestisci fonti** usare il formato repository `owner/name`, non un URL e non il suffisso `.git`. Sincronizzare l'anteprima, controllare file/heading, applicare allo stesso snapshot e salvare il progetto archiviato. Il runtime elimina l'esatta generazione del token allo shutdown.

Dettagli: [Catalogo fonti](COURSE_SOURCE_CATALOG.md).

## Preparazione docente

### 1. Progetto didattico

1. Creare o caricare un progetto archiviato.
2. Configurare fonti locali/GitHub/GitLab.
3. Sincronizzare e controllare la preview.
4. Inserire paragrafi nelle UDA.
5. Collegare activity come pratica o verifica.
6. Associare date e calendario.
7. Salvare con nome prima di impostare un progetto corrente.

`doc/course_design.json` è il progetto corrente; le copie sono in `doc/course_designs/`. Usare **Imposta corrente** soltanto dopo backup e conferma esplicita.

### 2. Activity

- creare la scheda con `scripts/create_activity.py`;
- validarla con `scripts/validate_activity.py`;
- definire runner, asset, modalità di aiuto e rubriche;
- non inserire soluzioni o test nascosti nello scaffold studente.

### 3. Classe e assegnazioni

- preparare roster e mapping interni;
- approvare utenti `pending` tramite amministrazione;
- creare scaffold e assegnazioni;
- verificare che ogni studente veda soltanto la propria classe e le proprie API.

### 4. Grading

- usare la toolchain bloccata;
- preferire sandbox Docker per codice non fidato;
- non montare segreti nei job studente;
- conservare report strutturati e fingerprint di activity/test.

## Flusso studente

### Accesso

Con autenticazione federata, lo studente accede via Google e viene autorizzato in base a ruolo e membership interni. Per la TUI usa il pairing browser-mediated: il browser non riceve il bearer terminale e il terminale non riceve cookie web.

### Laboratorio

La CLI/TUI è il canale studente autenticato dell'MVP. `student_dashboard.html` resta una vista locale protetta dalla Basic docente: non condividere quella credenziale con gli studenti e non pubblicare la pagina come self-service federato.

1. Elencare le consegne.
2. Aprire il dettaglio.
3. Leggere modalità di aiuto consentite.
4. Eseguire il runner.
5. Consultare test e storico tentativi.
6. Richiedere aiuto entro policy e budget.
7. Selezionare il tentativo definitivo quando previsto.
8. Effettuare logout per revocare la sessione esatta.

Dettagli: [Lab studente](STUDENT_LAB.md) e [guida dashboard studente](DASHBOARD_STUDENTE_GUIDA.md).

## Flusso di revisione docente

1. Aprire dashboard docente.
2. Selezionare activity e classe.
3. Generare o caricare il registro.
4. Controllare mancanti, ritardi e grading.
5. Aprire report e test falliti.
6. Leggere richieste di aiuto.

## Autenticazione federata del pilot

L'avvio con Google OIDC richiede configurazione esterna sicura e reverse proxy HTTPS trusted:

```powershell
python scripts/course_board_server.py --enable-google-auth
```

Per combinarla con fonti private:

```powershell
python scripts/course_board_server.py --enable-google-auth --enable-github-app-token-runtime
```

Non esporre direttamente HTTP non-loopback. Usare callback stabili e seguire [smoke staging auth](AUTH_STAGING_SMOKE.md).

- [ ] Primo admin creato tramite bootstrap one-shot.
- [ ] Ruoli e classi controllati senza SQL manuale.
- [ ] Backup completato e restore provato.
- [ ] Docker runner verificato in CI o host pilot.
- [ ] Fonti private accessibili con permessi read-only.
- [ ] Activity e test validati.
- [ ] Account demo docente/studente provati end-to-end.

- [ ] Procedura incident/revoca comunicata ai gestori.

## Backup e ripristino

Eseguire backup coerenti a processo fermo o tramite procedure SQLite appropriate. Includere:

- database identità;
- design, calendari, activity e roster;
- assegnazioni, report e binding grading;
- configurazioni non segrete necessarie al restore.

Non inserire chiavi OAuth, private key GitHub App o token nel backup applicativo non cifrato. Verificare periodicamente il ripristino in una directory isolata.

## Arresto

Usare `Ctrl+C`. Attendere il messaggio di arresto e verificare che:

- la porta non sia più in ascolto;
- i lock di processo siano rilasciati;
- installation token temporanei siano rimossi;
- non restino job grading non contabilizzati.

## Problemi comuni

| Sintomo | Controllo |
|---|---|
| Repository non valido | Usare `owner/name`, non URL o `.git` |
| GitHub API 404 su privato | App installata sul proprietario corretto e repository selezionato |
| Fonte obsoleta | Risincornizzare e riallineare esplicitamente commit/digest |
| HTTP 409 al salvataggio | Ricaricare la revisione e ripetere senza sovrascrivere modifiche altrui |
| Utente autenticato ma non autorizzato | Controllare ruolo/membership interni |
| TUI non accede dopo logout | Eseguire nuovo pairing; il bearer precedente è revocato |
| Docker non disponibile | Avviare il motore o usare evidenza CI; non disattivare la sandbox in produzione |

## Cosa non è ancora produzione multi-scuola

L'MVP non offre ancora tenancy forte, replica orizzontale, PostgreSQL, coda condivisa, object storage, worker distribuiti o osservabilità completa. Il pilot deve restare una singola installazione controllata finché queste precondizioni non vengono implementate e collaudate.
